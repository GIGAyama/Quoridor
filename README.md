# **🚧 カベカベ合戦！〜道を切り拓け〜**

GIGAスクール端末（Chromebook/iPad）で快適に動作する、教育用対戦パズルゲームです。

Vite + React 製のPWA（プログレッシブウェブアプリ）として動作し、Chromeなどのブラウザから「アプリとしてインストール」して利用できます。

公開先： https://gigayama.github.io/Quoridor/

## **🎮 ゲーム概要**

* **ジャンル**: 対戦型パズル（コリドール風）
* **プレイ人数**: 2人（1台の端末をシェアして対戦）
* **対象**: 小学生全学年
* **1局の目安**: 3〜10分（盤の大きさによる）
* **サーバー**: 無し。すべて端末の中だけで完結する

## **✨ このアプリでできること**

読んだだけで何ができるか分かるように、実装してある機能をすべて挙げる。

### ゲームとして

| できること | 中身 |
|---|---|
| 盤の大きさを3つから選ぶ | **5x5（かんたん）/ 7x7（ふつう）/ 9x9（むずかしい）**。既定は 9x9 |
| ハンデを付ける | 持ちカベの枚数を**青・赤それぞれ 0〜20枚**で設定できる。既定は 9x9 → 10枚、7x7 → 6枚、5x5 → 3枚 |
| 1手ごとに「動く」か「カベ」を選ぶ | 自分の番に、コマを1マス動かすか、カベを1枚置くかのどちらか |
| コマを飛び越す | 相手のコマと隣り合っているときだけ、まっすぐ**飛び越して2マス進める**（間にカベが無い場合） |
| カベを置く | カベは**2マス分の長さ**。タテ／ヨコを切り替えて置く。重なり・十字交差・盤外は置けない |
| 閉じ込めを自動で禁止する | どちらかのゴールへの道が完全に消える置き方は、幅優先探索で判定して置かせない（`src/rules.js`） |
| カベは2回で置く | 1回目のタップで置き場所が決まり、点線のカベで下見できる。2回目のタップ（または「ここに 置く！」）で確定する。**タッチ端末には hover が無く、これまでは押すまで置き場所が分からなかった** |
| 下見の途中でも直せる | ちがうマスを押せば下見がそちらへ移り、向きを変えれば場所はそのままでタテ⇄ヨコが入れ替わる。「やめる」／Esc で取り消せる |
| 置ける場所に印が出る | カベモードでは、いまの向きで置ける継ぎ目に小さな点を出す。押す前に見当が付く |
| 番が変わると「あるく」に戻る | 手番を渡すとモードは必ず「あるく」へ。前の子のカベモードのまま次の子が触れてしまう事故を無くす |
| 直前の1手が残る | 相手が置いたばかりのカベは枠で囲み、動いたコマは「どこから来たか」を点線で残す（次の1手まで） |
| 動けないマスを押したときに知らせる | 何も起きないと壊れたと思われるので、音と「光っているマスへ うごかしてね」の案内を出す |
| のこりカベが操作バーに出る | 「カベ ×10」と枚数を出し、0枚になったらボタン自体を押せなくする |
| 何手でも「待った！」 | 勝負が付くまで、1手ずつ何回でも戻せる |
| 勝敗の表示 | 反対側の端の列に着いたら勝ち。「もう一回遊ぶ」で設定画面へ戻る |
| 効果音 | 移動・設置・エラー・待った・勝利を Web Audio API で鳴らす（外部の音声ファイルは無し） |

### 教室で使うために

| できること | 中身 |
|---|---|
| 全ての漢字にふりがな（ルビ） | ルビの色は親から継ぐので、どの色のボタンの上でもコントラストが本文と同じ |
| 提示モード（「大きく表示」） | 電子黒板むけに文字と操作を一回り大きくする。合わせて全画面にもする（全画面にならない端末でも文字は大きくなる） |
| レスポンシブ | 縦・横・タブレット・PCのいずれでも盤面が最大サイズになる。横向きの低い画面では操作バーが画面右の縦バーへ移る |
| 視覚的なルール説明 | ナビの「？」から、絵で分かる4枚の説明を出す（3枚はルール、1枚はカベの置きかた）。画面より高いときは説明の窓の中だけがスクロールする |
| キーボードだけで遊べる | Tab で盤面へ入り、矢印キーで選び、Enter / Space で決める。カベの下見中は矢印キーで下見ごと動き、Esc で取り消せる。Esc でモーダルも閉じる |
| 読み上げ対応 | 手番・のこりカベ・勝敗を `aria-live` で読み上げる。マスには「〇だん 〇れつ」のラベルが付く |
| ハイコントラスト / 動きを減らす設定に追従 | `forced-colors` と `prefers-reduced-motion` に対応 |

### 学校のネットワーク・端末事情のために

| できること | 中身 |
|---|---|
| オフライン対応 | 一度読み込めばオフラインで遊べる（Service Worker）。本体が無いときは `offline.html` を出す |
| アプリとしてインストール可能 | ホーム画面に追加して全画面で起動できる。案内できるときだけ「アプリにする」ボタンを出す |
| 更新は押すまで待つ | 新しい版が届いても勝手に切り替えない。トーストの「さいしんに する」を押したときだけ入れ替える（対戦中に盤面が消えないため） |
| 真っ白から自力で復帰できる | 本体が描けないと「うまく ひらけませんでした」の画面が出て、再読み込み／ほぞんを消す ボタンで直せる（`public/boot-check.js`）。JSが1本も動かない場合でも、HTML+CSSだけの案内が10秒後に出る |
| アドレスだけで一斉に直せる | URL の末尾に `?fix=1` を付けて開くと、その場でこのアプリのキャッシュと Service Worker を消して開き直す |
| 記録を残さない | 名前も点数も保存せず、どこにも送信しない。`localStorage` も使っていない |

先生向けの使い方は [MANUAL.md](./MANUAL.md)。

## **📂 プロジェクト構成**

```
├── App.jsx                    # ゲーム画面（UI・入力・音・モーダル）
├── index.html                 # エントリHTML（CSP・PWAメタタグ・install-hook・boot-check・真っ白時の控え）
├── src/
│   ├── main.jsx               # Reactエントリ（SW の登録もここから）
│   ├── rules.js               # ゲームの決まり（画面に依存しない判定。テスト対象）
│   ├── pwa.js                 # Service Worker の登録と更新の案内
│   └── styles.css             # レイアウト・レスポンシブ・提示モード・印刷
├── public/
│   ├── manifest.webmanifest   # PWAマニフェスト（id/scope/start_url は /Quoridor/）
│   ├── sw.js                  # Service Worker（オフラインキャッシュ）
│   ├── install-hook.js        # beforeinstallprompt の捕捉（head の先頭で読む）
│   ├── boot-check.js          # 真っ白のときに直しかたを出す番人（?fix=1 もここ）
│   ├── offline.html           # 圏外で本体も無いときに出す画面
│   ├── favicon.png            # 生成物
│   └── icons/                 # PWAアイコン（192/512/maskable/apple-touch）
├── tests/
│   └── rules.test.mjs         # ゲームの決まりのテスト
├── tools/                     # 実測ツール（実ブラウザで測る）
│   ├── measure-lib.mjs        #   実測ツール共通（配信サーバ・ブラウザ起動・集計）
│   ├── measure-ui.mjs         #   コントラスト・タップ領域・横スクロール・CSP違反
│   ├── measure-pwa.mjs        #   登録・更新・圏外・他アプリのキャッシュ
│   ├── measure-a11y.mjs       #   キーボード操作・モーダル
│   ├── measure-icons.mjs      #   透明・maskable のセーフゾーン（画素を数える）
│   ├── measure-boot.mjs       #   真っ白からの復帰（本体の js をわざと 404 にする）
│   ├── build-icons.mjs        #   アイコン一式を作り直す
│   └── icon-master.png        #   アイコンの元画像（ここを直して build-icons を走らせる）
├── scripts/
│   ├── check-project.mjs      # 品質ゲート（--self-test 付き）
│   └── lib/giga-v5-checks.mjs #   Part I の静的検査
├── .github/workflows/
│   ├── ci.yml                 # 上の検査と実測をまとめて走らせる
│   └── deploy.yml             # GitHub Pages への配信（配信元は GitHub Actions）
├── quality.config.json        # 品質ゲートのしきい値
├── vite.config.js             # base:'./' と、先読みリストを sw.js へ埋める処理
├── tailwind.config.js
├── postcss.config.js
├── eslint.config.js
├── MANUAL.md                  # 先生向けの手引き
└── AUDIT.md                   # 実測値と、測っていないものの一覧
```

### **手で編集してよいもの／いけないもの**

| ファイル | |
|---|---|
| `App.jsx` `src/*` `public/*` `index.html` | **ここを直す** |
| `dist/**` | 生成物。手で編集しない |
| `dist/sw.js` の `BUILD_ASSETS` 行 | ビルド時に `vite.config.js` が埋める。手で書かない |
| `public/icons/*` `public/favicon.png` | 生成物。`tools/icon-master.png` を直して `npm run icons` |

**アイコンを直したら `npm run icons` を、原本を直したら `npm run build` を走らせてから push すること。**

配り直すときは `public/sw.js` の `APP_VERSION` を上げる。上げないと、端末に残った古い版が使われ続ける。

## **🚀 開発・ビルド**

```bash
npm install        # 依存関係のインストール
npm run dev        # 開発サーバー起動
npm run lint       # ESLintチェック（警告も0件でないと落ちる）
npm test           # ゲームの決まりのテスト（node --test）
npm run build      # 本番ビルド（dist/ に出力）
npm run preview    # ビルド結果の確認
npm run icons      # アイコン一式を作り直す（tools/icon-master.png から）
```

`dist/` を任意の静的ホスティング（GitHub Pages、Netlify、Cloudflare Pages等）に**HTTPSで**配置してください。PWAのインストールとService WorkerはHTTPS環境（またはlocalhost）でのみ有効です。

このリポジトリでは `.github/workflows/deploy.yml` が `main` への push で GitHub Pages へ配信します。
**Pages の配信元（Settings → Pages → Source）は「GitHub Actions」にしておくこと。**
「Deploy from a branch」にすると、ビルド結果ではなくソースがそのまま配られ、画面が真っ白になります。

## **✅ 品質ゲートと実測**

読めば分かることは品質ゲートで、読んでも分からないことは実ブラウザで測る。
**CI（`main` への push と、すべての pull_request）で全部走る。**

```bash
npm run check            # lint → test → build → gate → measure をまとめて（push 前にこれを通す）

npm run gate             # Part I の静的検査
npm run gate:self-test   # 検査そのものが動くか（わざと壊して落ちるか確かめる。check には含まれない）
npm run measure          # 下の measure:* を全部
npm run measure:ui       # コントラスト・タップ領域・横スクロール・CSP違反・JSエラー
npm run measure:pwa      # SW の登録・更新・圏外・他アプリのキャッシュ
npm run measure:a11y     # キーボードだけで1手指せるか・モーダルの作法
npm run measure:icons    # アイコンの透明・maskable のセーフゾーン（画素を数える）
npm run measure:boot     # 本体が読めないときに、画面から自力で直せるか
```

`measure:*` は `dist/` を配って測るので、先に `npm run build` が要る。
実測には Chromium が要る（`npx playwright install --with-deps chromium`）。

**検査を足したら、`scripts/check-project.mjs` の `BREAKS` に「壊し方」も足すこと。**
「0件でした」だけでは、検査が動いているのか何も見ていないのか区別が付かない。
実際、この自己確認で検査そのものの不具合が3件見つかっている。

実測値と、測っていないものの一覧は [AUDIT.md](./AUDIT.md) にある。

## **🔒 セキュリティ設計**

* **外部への通信が1本も無い。** CDN・Web フォント・解析・API すべて使っていない。
  学校のフィルタリングで何が塞がれても、このアプリは起動する。
* **CSP を `index.html` の `<meta>` で入れている**（`script-src 'self'`）。
  インラインの `<script>` と `onclick=` は使っていない。
  `style-src` にだけ `'unsafe-inline'` が要る（盤面のマス目の位置を React の style 属性で計算しているため）。
  `frame-ancestors` は `<meta>` では無視されるので書いていない
  （独自ドメインや CDN を挟むときは、そちら側で HTTP ヘッダーとして設定すること）。
* **個人情報を持たない。** 名前・出席番号を入力する欄が無く、`localStorage` も使っていない。
* **Service Worker は自アプリ接頭辞（`kabe-kabe-`）のキャッシュだけを消す。**
  `gigayama.github.io` は複数アプリで同一オリジンを共有しているため、
  `caches.keys()` の全削除は他アプリのオフラインを壊す。
  `boot-check.js` の「なおす」と `?fix=1` も、同じ理由で自アプリ分だけを消す。

## **📐 制限**

* 9x9 の盤を 320x568 の画面で開くと、1マスが 25.3px になる（44px には物理的に届かない）。
  5x5 / 7x7 を選ぶか、キーボード操作（矢印 + Enter）で補う。
* 320x568 では**縦のスクロール**が残る（盤面を優先し、のこりカベのパネルが画面外へ出る）。
  横のスクロールは 0px。
* 記録を残さない。閉じると盤面は消える。**「待った！」の履歴も、閉じると消える。**
* 2人が1台を交代で使う設計。通信対戦・CPU対戦は無い。

## **📱 インストール方法（児童・生徒向け）**

1. ChromeでアプリのURLを開く
2. 画面上の「アプリにする」ボタン、またはアドレスバー右端の「インストール」アイコン
   （またはメニュー →「アプリをインストール」）をタップ
3. ホーム画面 / デスクトップに追加されたアイコンから、アプリとして全画面で起動できます

iPadのSafariでは「アプリにする」ボタンは出ません。「共有」→「ホーム画面に追加」でインストールできます。

## **🕹️ 遊び方**

1. **準備**: 2人ペアになり、1台のタブレットを机の真ん中に置きます。
2. **設定**: 盤の大きさ（5x5 / 7x7 / 9x9）と、青・赤それぞれの持ちカベの枚数を決めて「ゲーム開始！」。
3. **チーム決め**: 「青チーム（左端から出て右へ進む）」と「赤チーム（右端から出て左へ進む）」を決めます。青が先手です。
4. **アクション**: 自分の番が来たら、以下のどちらか1つを行います。
   * 🏃 **歩く**: コマを1マス進める（上下左右）。光っているマスを押します。
     相手のコマと隣り合っているときは、まっすぐ飛び越して2マス進めます。
   * 🚧 **カベ**: 相手のジャマをするためにカベを置く。
     「カベ」を押してモードを切り替えると、置ける継ぎ目に小さな点が出ます。
     **置きたいところを1回押すと点線のカベで下見**になり、**もう一度押す**か「ここに 置く！」で決まります。
     場所を変えたいときは別のところを押し、向きを変えたいときは右の「むきは タテ／ヨコ」を押します。やめるときは「やめる」。
5. **勝利条件**: 先に反対側の端っこの列にたどり着いたチームの勝ち！

なお、**手番が変わると操作は必ず「あるく」に戻ります**。前の人がカベモードのままでも、次の人はいつも同じ状態から始められます。

## **⚠️ 注意事項**

* **カベのルール**: 相手がゴールできなくなるような「閉じ込め」配置はできません（システムが自動で判定してエラーを出します）。自分のゴールを塞ぐ置き方も同じく禁止です。
* **カベは有限**: 持ちカベを使い切ると、コマを動かすしかありません。
* **オフライン**: 初回アクセス時にアプリ全体がキャッシュされるため、2回目以降はオフラインでも動作します。
* **うまく開けないとき**: URL の末尾に `?fix=1` を付けて開くと直ります。詳しくは [MANUAL.md](./MANUAL.md) の「7. うまくいかないとき」。
