# note 入稿メモ（カベカベ合戦！の紹介記事）

このフォルダの中身は次の3つです。

- `kabekabe-note-article.md` … 記事本文。note にそのまま貼れる形
- `images/` … 実際にアプリを操作して撮った画面（21点）
- `README.md` … このファイル

---

## 貼るまえに直すところ

### 1. 連載番号

タイトル1行目の `#◯` を、実際の番号に置きかえてください。
ここだけは推測で埋めていません。番号を間違えると連載が崩れるためです。

```
# 教室で使えるかもしれないもの作り #◯ 「それ反則だよ！」でけんかにならない。…
```

### 2. 前作へのリンク（必要なら）

このアプリを前に紹介した記事があるなら、「🏫 はじめに」の URL のあとに
一文足すと、連載の読者にとって記事の位置がはっきりします。
今回はその有無を確認できなかったので、書いていません。

### 3. タイトルの言いまわし

長いと感じたら短くしてください。型は
「（読み手が困っていること）」（アプリの持ち味）アプリ「名前」です。
いまは「それ反則だよ！」でけんかにならない、を困りごとに当てています。

## note に貼る手順

1. note のエディタを開き、タイトル欄に本文1行目の `#` を外したものを入れる
2. 本文の2行目以降を、そのままコピーして貼る
3. 見出し（`##` の行）は note 側で見出しとして認識されます。目次はここから自動で作られます
4. 画像は自動では入りません。`![…](images/…)` の行を消しながら、同じ位置で
   画像を1枚ずつアップロードしてください。順番は下の対応表のとおりです
5. 画像の直後にある1行の説明は、note の画像キャプション欄へ移します。
   本文に残したままでも読めますが、キャプション欄のほうが収まりがよいです
6. ハッシュタグ欄の候補
   `#GIGAスクール` `#小学校` `#教育ICT` `#プログラミング` `#自作アプリ` `#Chromebook`

本文には太字も表も使っていません。note のエディタで崩れる要素は入っていないはずです。

## 撮り直すときの手順

撮影用のスクリプトはリポジトリに残していません。次の手順で作り直せます。

1. ビルドして、本番と同じサブパスの下で配る

```bash
npm run build
node <skill>/scripts/serve.mjs dist 4180 /Quoridor/
```

2. シナリオを書いて撮る。盤のマスは `<button>` ではなく `div[role="gridcell"]` なので、
   `capture.mjs` の `click()` では拾えません。`aria-label`（`5だん 1れつ、…`）の
   先頭で照合して押すヘルパーが要ります

```js
const tap = (p, r, c) => p.eval(([r, c]) => {
  const el = [...document.querySelectorAll('[role="gridcell"]')]
    .find((e) => (e.getAttribute('aria-label') || '').startsWith(`${r}だん ${c}れつ`));
  if (!el) return false; el.click(); return true;
}, [r, c]);
```

3. 撮るときに気をつけたこと

- ビューポートは 390x820 が収まりがよい。940 にすると下に余白が出る。
  あそびかたの説明だけは 390x1560 にすると4枚とも1枚に収まる
- 「光っているマスへ うごかしてね」の案内は1.8秒で自分で消える。押した直後に撮る
- カベの向きを変えて置けなくなると、その場でお知らせが出て 1.5秒で消える。
  お知らせ（`16`）と、消えたあとの「置けません」の状態（`17`）は別々に撮る
- 閉じこめの状態を作るには、赤のコマを右上のすみへ寄せてから、
  ヨコのカベを `2だん 8れつ` に置き、赤を1マス下げて、`1だん 8れつ` を狙う。
  この位置はヨコなら置けてタテなら置けないので、1か所で両方の状態が撮れる

4. 撮った PNG を再圧縮してから `docs/note/images/` へ入れる

```js
import sharp from 'sharp';
await sharp(src).png({ compressionLevel: 9, effort: 10 }).toFile(dst);
```

色は変えない再圧縮です。これだけで 150KB から 400KB あったものが
57KB から 141KB まで落ちて、`npm run gate` の上限に収まります。

5. 撮影用のシナリオは `node_modules` の都合でリポジトリの中に置くことになります。
   `.tmp-shots/` のような分かる名前にして、終わったら消してください。
   `npm run lint` はリポジトリ全体を見るので、消し忘れると
   `document is not defined` で落ちます

## 撮影中に見つかった不具合

ありません。21点を撮るあいだ、画面のエラーも、動かない機能もありませんでした。
`npm test`（11件）と `npm run gate` も、この作業の前後で通っています。

なお `npm run gate` は、`.tmp-shots/` に撮ったままの PNG を置いた状態だと
D7_IMAGE_SIZE で落ちます。上の再圧縮を通したあとの `docs/note/images/` は
21枚すべて上限内です。
